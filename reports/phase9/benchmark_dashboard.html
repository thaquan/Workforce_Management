Benchmark without invented performance claims.

Reproducible synthetic data, ZSTD Parquet and SQL query measurements. All numbers below were measured locally; they are not a production benchmark and do not describe the actual HR dataset.

Experimental method. Five-percent existing-row updates and one-percent new records; deterministic integer-only synthetic records. Each DuckDB query is warmed up, then timed three times for published scales. The charts show per-scale query median and compressed file size, not full-pipeline latency.

Interpretation

Measured elapsed time depends on the machine, engine settings, cache state and selectivity. Bar lengths compare scales within each metric only. No speedup is claimed where PostgreSQL full-load and incremental workloads were not measured. The separate PostgreSQL 1K smoke test checks correctness, not capacity.

Privacy & integrity: All source rows were generated from integer formulas. No real names, salary records, IDs or original HR workbook were loaded. Full-row PostgreSQL correctness and cross-engine aggregate equality must pass before any comparative claims. See docs/phase9/README.md for commands.
